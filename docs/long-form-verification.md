# 长篇阅读与改稿验证

验证日期：2026-10-11（Asia/Shanghai）。实现依据见 [已确认设计](long-form-reading-design.md)，步骤见 [实施计划](superpowers/plans/2026-10-11-long-form-reading.md)。

## 已验证的用户流程

- 阅读／审阅切换、连续邻章读取、章号／标题定位、分页正文原文搜索、字号／行距／宽度与段落位置恢复。
- 选区批注、审阅基准、已审正文修改后的差异、原文重复引文定位。单纯的上游复核状态变化不让重复引文失去位置；正文确已改动且引文不唯一时保留批注并提示重新定位。
- 选区交给 Agent，仅替换指定位置；单章直接保存与历史恢复。批注可以选择后交给 Agent，由作者复核关闭。
- 多章待审稿不覆盖原文，按章或批次采纳；生成时读取过的邻章被手改会阻止旧稿采纳，依赖其他待审稿的候选须先处理关联章或一起采纳。
- 范围、覆盖进度、Token 预算、暂停、澄清、取消、退出与手动续跑。暂停／取消保留待审稿。关联资料只在所有相关候选一致后统一采纳。
- 手动分卷与普通对话分卷建议。建议不会触发全文改稿任务或自动移动正文。
- 作品包 v4 携带阅读与改稿数据，旧 v1／v2／v3 继续可导入；副本身份重映射、待审稿采纳及暂停任务续跑验证通过。

`scripts/verify-long-form.ts` 使用真实 SQLite 创建 5,000 章、15,000,000 字符正文及两份完整非空历史（10,000 个版本）。

| 数据不变轮询 | 仅返回修订号 |
| 仅阅读位置变化 | 不重传全书目录 |
| 作品包大小 | 139,055,623 字节 |

## 真实模型

隔离样本使用本机已配置的官方 DeepSeek `deepseek-flash`，最新验证共 3 次模型调用，报告用量 2,202 Token：

- 精确替换第二处重复引文，区外正文保持一致，保存为当前稿并保留历史。
- 两章统一人名，2／2 章生成待审稿；采纳前原文保持一致，采纳后准确修改全部目标。

证据见 [最新真实验证](long-form-live-evidence.json)。首次多章验证中模型输出包含参考邻章，应用拒绝保存；已加强每轮唯一可回写 ID 的约束后复验通过。该失败证据保留在 [首次验证](long-form-live-first-attempt.json)。生产小说数据库仅用于只读读取模型配置；所有样本在隔离数据目录运行并清理。

## 边界与交付

全书改稿逐章读取完整来源，并提供有界邻章与资料参考，不把完成覆盖等同于保证发现一切跨章矛盾。超长完整章节或设定超出上下文时暂停；超限资料明确列为未覆盖，不用截断正文覆盖原稿。Token 预算与费用不同，默认总预算 100,000，可在显式续跑时提高。跨机续跑须有相匹配的模型配置。
