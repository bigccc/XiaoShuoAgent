# 第三阶段：场景卡与定向修订

2026-10-14。用户「继续」授权路线图第三阶段，沿用原生实施及末尾一次独立审查，不再重问执行方式。保留作者三步流程、正文版本、恢复和已有预算控制。

## 场景计划

每章最多一份当前计划，独立scenePlans保存稳定ID、版本、2—4张场景卡及最多50个历史版本。卡片有title、pov、goal、obstacle、turn、reveal、words、hook；每卡words为1—16000整数，合计等于本章计划targetWords（1—16000）。计划是写作方向而非已发生事实，不提交为故事状态。卡片可绑定本章原文选段，逐字/偏移/版本校验，重复原文须作者选择具体位置。

场景规划默认融入连续写作的同一次生成响应：提示先规划2—4卡再写正文，响应可附scenes，保存新稿后保存卡片与可定位原文；不新增默认AI请求，也不强制作者确认每卡。老模型未返回可选卡片时保持兼容；无效卡片警告，完整正文仍保留。有作者保存的有效计划时先把该计划放进生成输入，模型不能用附带卡片覆盖作者计划。原文/资料/状态来源变化使计划需复核；明确编辑保存或重建后才再用，不能悄悄使用失效计划。

作者按需展开「本章场景」后可提前生成计划（明确的独立AI请求）、新增/删除/编辑2—4卡、保存或恢复历史。来源标签及陈旧提示可见；整章篇幅与各卡合计同时显示。未保存编辑沿用导航保护。只在展开时按需读取计划/历史，poll不传全量卡片或历史。

## 显式规划任务

sceneJobs持久化单章范围、原计划版本、原文/资料/状态来源、调用/预算和进度，默认100000/最大1000000 Token，单次输出上限4000、最多1次provider尝试。调用前预留，未知用量保留预留值。预算不足暂停；取消/失败/重启保留旧卡片，重启不自动调用。续跑重新验证原始来源，导入只在明确继续时绑定本机规划/写作连接。作者改计划或原文后旧回复不能覆盖。

## 定向修订

从卡片选择逐字原文绑定，要求可写目标/阻力、转折、视角、删冗余、补冲突等具体指令。scene.revise转换为带sceneSource的RevisionRunner选段任务：只给出绑定片段，服务端拼接原前缀和后缀，标题保持原值；结果进入已有待审稿，不自动采纳。重大方向变更或歧义只返回说明，暂停等作者决定。采纳/续跑/返回时核对卡片版本、计划版本、完整正文和已读取资料/故事状态，作者编辑后旧候选不能覆盖。

## 存储与验收

SQLite/作品包升v7，v6迁移前备份，v1—v6补空场景表；身份、历史、选段与改稿sceneSource重映射，跨作品引用/伪造当前原文原子拒绝，原本有效的状态摘要重建，失效摘要不刷新。模型配置和密钥不随包导出。
