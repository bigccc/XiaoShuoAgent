# 网文创作桌面 App 首版规格

日期：2026-10-06。

状态：2026-10-06 用户回复「OK」确认完整规格并进入开发。前三轮要求来源于 `product-design.md`；下文「拟议」默认值随本次整体确认接受，实施发现的问题需记录调整依据。本文不是功能已实现或已通过测试的声明。

## 1. 产品目标与交付形态

提供个人网文创作工作台，从一句创意逐步形成设定、大纲、章纲和正文，支持作者主导的 AI 创作、修订、检查、导出与迁移。

- 可安装的 macOS App；分别提供 Apple Silicon 和 Intel 的安装包并验证。
- 使用者无需安装 Node.js、Python、数据库服务或配置开发环境。
- 作品存储在本机；每位使用者自行配置模型 API 地址、密钥和模型名称。
- 支持保存多个模型配置，分别用于规划、正文、检查。
- Windows、账号付费、多人协作、云同步、主动抓取热点和网页解析留作后续扩展。
- 拟议：界面默认简体中文；采用直接分发安装包，首版不以 Mac App Store 上架或自动更新为交付条件。
- 拟议：离线可阅读、编辑、管理、导出和备份已有内容；API 生成与 AI 检查需要网络。

## 2. 页面与创作流程

拟议工作台结构：书架 → 单部作品工作台；工作台左侧导航，中间编辑，右侧显示当前步骤的 AI 建议、素材和检查结果。

| 工作区 | 作者操作 | AI 辅助 |
| --- | --- | --- |
| 书架 | 创建、打开和管理多部独立作品 | 根据创意建议书名与简介 |
| 创意与风格 | 填写名称、背景、题材、文风、节奏、字数目标 | 提炼看点与核心冲突 |
| 设定 | 编辑人物、关系、世界规则、场景与地点 | 补全建议、指出矛盾 |
| 故事规划 | 调整主线、支线、全书及分卷大纲、近期章纲 | 提出结构、爽点和转折 |
| 正文 | 编辑、确认、重写、对比和恢复版本 | 按章纲生成正文或对所选内容提出改写 |
| 一致性检查 | 查看证据、处理或忽略问题 | 检查人物、时间、地点、规则、知情范围及伏笔 |
| 素材库 | 导入、检查提取结果、选用素材 | 提取网络表达与剧情套路、解释适用条件 |
| 设置与任务 | 配置模型、查看任务状态与用量 | 展示执行进度和失败原因 |

已确认引导顺序：创意与看点 → 核心人物及世界设定 → 主线与支线 → 全书／分卷大纲 → 近期章纲 → 正文。

作者可以修改、补充、重做和返回前一步；不要求一次性规划整部小说的所有章纲。

拟议：首版以新建作品为入口；把已有整本小说自动拆分成全部设定与章节属于后续扩展，不把素材导入解释成作品结构导入。

## 3. 内容对象与来源

领域术语以根目录 `CONTEXT.md` 为准。

- 小说：名称、简介／背景、题材、文风、叙事节奏和目标规模。
- 人物：拟议包含身份、目标、性格、说话习惯、关系与当前状态。
- 世界设定：拟议包含时代、规则、组织与限制。
- 场景／地点：拟议区分故事发生的空间设定与某章发生的具体事件；界面应避免二者混淆。
- 规划：主线与支线、全书／分卷大纲、章纲。
- 正文：章节内容、确认状态、版本、是否需要复核。
- 一致性记录：时间线、角色知情信息与伏笔进展。
- 素材：原始来源备注、提取内容、类型、适用条件及引用关系。

拟议：AI 从正文提取的事实、摘要和伏笔记录保留来源章节与版本。它们是可复核记录，不自动覆盖作者确认的设定。

## 4. 按章生成与作者确认

1. 作者确认创作设定与规划，选择章节或明确授权连续生成 3—5 章。
2. 系统参考章纲、关联设定、相关前文记录和适用素材生成草稿。
3. 同批次后章可使用前章草稿作为上下文，但不能因此把草稿标为已确认正文。
4. 发现重大剧情变化或设定冲突时暂停，显示原因并交由作者处理。
5. 作者可以手动编辑、要求重写、比较版本，然后确认正文。

拟议细则：

- 默认只将已确认正文作为跨批次的稳定依据；存在前置未确认草稿时，需明确选择把它们纳入本次工作上下文。
- 生成中的部分文本单独保存；中断不把片段标为完成章节。
- 作者修改当前生成依据时，当前结果标记为需要复核，不静默替换其正在编辑的内容。
- 恢复旧版本形成新的当前版本，保留恢复前的记录。
- AI 检查无法保证发现所有冲突；人工阅读是验收的一部分。

## 5. 设定修改与一致性

已确认检查范围：人物与关系、时间线、地点、世界规则、角色知情范围、伏笔进展。

每条问题应提供对应原文、来源章节或设定、原因；作者决定是否处理。涉及跨章冲突时，拟议同时展示两边的依据。

设定或前章修改后：

1. 列出已知受影响的设定、规划和后文，标记需要复核。
2. AI 提出修订建议；作者选择修改目标。
3. 不直接覆盖已确认正文；重写保留旧版本。
4. 拟议使对应摘要与提取记录失效并重新计算，避免继续使用旧版本的记录；无法确定影响范围时明确提示检查范围有限。

## 6. 风格与素材

- 题材、文风、节奏分别配置；作品设定默认值，章节可调整语气和节奏。
- 保持角色说话习惯及整体叙述连贯性；不承诺仅靠一个风格标签保证效果。
- 首版支持粘贴文字及上传 TXT／Word，提取网络表达、段子、桥段、人物关系、爽点和反转模式。
- 提取后由作者检查再入库；保存来源备注，规划时推荐适用素材，由作者选用或明确授权 AI 自行选用。
- 素材使用需考虑故事时代、人物身份与当前情节。
- 拟议：Word 输入首版限定 `.docx`，旧 `.doc` 给出转换提示；导出 Word 使用 `.docx`。
- 拟议：素材库可跨作品复用，作品保留引用素材快照，以保证导出备份后仍可追溯。
- 拟议：没有热度来源时只标为候选表达／套路，不凭 AI 提取结果声称已验证「爆款」。

## 7. 任务、失败与用量

- 显示每次任务的进度、调用次数和服务商返回的用量。
- 网络临时错误最多自动重试两次；认证错误、配置错误应直接提示修正。
- 中断保留已完成章节和未完成片段，作者选择继续或重写；质量问题不无限自动重写。
- 单次任务允许设置用量上限。
- 拟议：模型配置提供连接测试；错误提示区分连通、鉴权、不支持的模型及返回格式问题。
- 拟议：任务状态为等待、执行中、待作者处理、已完成、已失败、已取消或已中断。取消、重启和重试不重复插入已保存章节。
- 拟议：多章任务使用配置快照，避免执行中更换模型配置影响已开始的任务。
- 拟议：明确区分服务商返回用量与估算值；缺少用量时不显示为零。仅有 Token 上限不能宣称精确金额封顶；发起后续调用前检查预算，限制单次请求输出长度。价格估算需要有效价格配置，首版不预填未核实价格。

## 8. 保存、导出与迁移

- 自动保存编辑内容并定期备份，界面展示保存结果；不能在保存失败时显示成功。
- 正文导出 TXT 或 Word；完整作品备份包含设定、大纲、正文版本与引用素材。
- 另一台 Mac 可导入完整作品备份，恢复创作资料；API 密钥不进入备份。
- 拟议：默认导出已确认正文，也可明确选择包含草稿，导出前列出未确认章节。
- 拟议：备份使用带格式版本及完整性校验的作品包；导入先验证，默认导入为副本，避免覆盖同名作品。
- 拟议：自动保存采用短暂防抖；编辑后每 15 分钟创建恢复备份并滚动保留最近 20 份，重要迁移前另建备份；手动导出的作品包不自动清理。
- 拟议：App 升级迁移数据前备份，迁移失败不破坏原作品。

## 9. 技术方案

拟议采用 Electron + React + TypeScript + SQLite，由 Electron Forge 打包。界面、创作编排与文档处理以 TypeScript 为主，避免使用者额外安装后端运行环境。选择理由及替代方案见 `adr/0002-electron-desktop.md`。

| 边界 | 职责 |
| --- | --- |
| 界面进程 | 编辑、规划、审阅、任务进度与模型配置表单 |
| 桌面主进程与受控任务执行层 | 文件访问、数据库、密钥保护、API 调用、取消和恢复 |
| 创作领域模块 | 作品设定、规划、正文版本、变更影响与确认规则 |
| 上下文组织模块 | 选择有关的设定和前文、生成可追溯摘要、区分确认内容与批次草稿 |
| 模型适配层 | 请求及流式响应、模型能力差异、用量与错误分类 |
| 导入导出模块 | TXT／DOCX、作品包校验、导入副本和数据迁移 |

界面采用受限操作接口访问本地能力，不向界面暴露任意文件访问或解密接口；模型返回文本与导入素材作为内容处理。按 [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)启用上下文隔离与沙箱，并验证进程间请求。

API 密钥由主进程通过 `safeStorage` 加密保存，macOS 使用 Keychain 保护加密密钥；加密密文也排除在作品备份之外。升级后的凭据访问需使用一致的发布签名进行验证。依据：[safeStorage 官方说明](https://www.electronjs.org/docs/latest/api/safe-storage)。

SQLite 负责作品、任务和版本持久化；附件放在受管理的应用数据目录。制作备份时生成一致快照，不直接复制正在写入的数据库主文件。依据：[SQLite 适用场景](https://www.sqlite.org/whentouse.html)、[Backup API](https://www.sqlite.org/backup.html)。若使用原生驱动，需针对 Electron 和各目标架构重建，并在实际安装包中验证，依据：[原生模块说明](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)。

拟议首个模型适配器支持 OpenAI 兼容的聊天生成接口；提供自定义地址、模型名和能力配置，其他协议可扩展适配。协议兼容性必须通过真实服务测试，不宣称任意 API 地址均可直接使用。具体模型由作者配置，开发时再核实可用服务与接口文档。

拟议直接分发 arm64 与 x64 安装包；以 DMG 为默认交付形式。开发构建、安装包构建、真实安装、签名和 Apple 公证分别验收。要让普通使用者无需绕过系统安全检查，需要相应签名和公证；当前尚未核实证书、凭据和两类测试设备。依据：[Forge 的 macOS 签名公证指南](https://www.electronforge.io/guides/code-signing/code-signing-macos)。

具体依赖版本和最低 macOS 版本在实施时根据选定 Electron 稳定版本、编辑器及数据库驱动支持范围确定，并标在安装说明中；不把本次文档核查当成安装验证。

## 10. 首版验收

| 验收项 | 通过依据 |
| --- | --- |
| 安装与启动 | 两类 Mac 分别实际安装启动，无需开发环境；构建出文件不能替代另一架构的实际安装测试 |
| 创作流程 | 从新建作品到设定、故事线、大纲、章纲、正文、确认与导出完整操作 |
| 手工编辑与版本 | 内容自动保存，重启后存在；重写可比较，恢复旧版不丢失新版记录 |
| 素材 | 文本、TXT、DOCX 提取可审阅并入库，选用素材可追溯到来源 |
| 模型接入 | 使用真实配置分别测试规划、正文、检查路径；同一模型兼任时也验证三种用途 |
| 草稿连续性 | 同批后章使用前章草稿，修改前章后相关内容标为需要复核，确认状态不被自动提升 |
| 一致性检查 | 注入确定的冲突样例并核对原文依据，同时人工检查误报；不以通过样例声称能识别所有冲突 |
| 失败与用量 | 模拟网络失败、取消、重启及预算耗尽，确认有限重试、内容保留和无重复章节 |
| 导出与迁移 | TXT／DOCX 实际打开核对章节顺序与中文内容；完整备份导入后比较设定、正文版本和素材，确认不包含密钥 |
| 长篇质量 | 都市轻喜剧样例连续二十章，每章目标约 3,000 字；真实生成后人工评估可读性、人物与情节连贯性，记录问题与修订 |

代码检查、自动化测试、真实 API 调用、二十章阅读验收、两种架构安装测试、签名公证和对外分发分别记录状态。未执行的验证明确标为未执行。

## 11. 实现顺序建议

1. 桌面运行、本地保存、作品与模型配置，打通一章真实生成及导出。
2. 完成设定、故事线、大纲、章纲、正文编辑与版本恢复。
3. 加入相关上下文组织、一致性检查、批量生成、恢复及用量限制。
4. 加入素材提取、完整备份迁移、两类安装包与完整验收。

以上为递进实现顺序，不缩减本文确认后的首版功能范围。
