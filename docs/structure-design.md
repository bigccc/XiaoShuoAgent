# 第六阶段：结构导航

2026-10-14。用户继续第六阶段，沿用原生实施、红绿回归及一次独立审查。保持创作/看稿/故事资料三项主导航，不增加工作流画布，不调用生产或付费模型、不安装或发布。

## 导航与作者计划

“看稿 → 结构导航”提供场景、主支线、人物出场、视角和伏笔五种投影，每页最多40条，可按章序范围/文字/人物/支线筛选。正文不进入导航批量响应；人物定位按姓名与最多11个明确别名的文字提及，并说明提及不等于实际在场。场景/视角来自作者计划，伏笔候选、计划和已采纳状态明确区分。原文打开时只加载所选章节。

新增structureWorkspaces，作者手工维护最多50条主线/支线，每条标题120字符、说明1000字符，场景关联总计最多1000条。关联记录章节/计划/卡片ID及卡片版本；其他作品或未知场景不能写入，移除/修改的场景保留旧关联并显示待复核。更新关联是作者明确保存，模型不能自动改线程。归档可找回；最多10版工作区历史，恢复保留原关联版本，不能补造新授权。

提醒限于可核实元信息：缺少视角、关联场景改变/移除、来源版本改变、已确认正文达到预期回收章但已采纳伏笔仍处埋设/推进。提醒展示具体理由，不认定文学缺陷或自动修改正文。每作品最多1000条忽略记录；忽略按来源版本指纹生效，依据改变后重新出现，可查看并恢复已忽略提醒。未采纳回收候选不能关闭已采纳埋设提醒；正常已确认回收/放弃不提醒逾期。

## 范围明确的修订

选择“视角一致、主支线衔接、人物表达、伏笔回收、删减重复、补足阻力”并编辑修改说明。作者点击生成待审稿才发请求；默认预算100000 Token，高级设置可调整。场景须绑定原文，通过已有sceneSource/selection保护只改绑定片段；章级入口明确只改当前一章。点击时校验当前版本，模型回复及采纳沿用现有版本/来源保护和重大方向暂停；正文不会直接覆盖。来源失效或场景未绑定时先定位原文复核。

## 按需查询与持久性

主进程分页查询场景/章元信息；人物匹配在SQLite筛选，返回页内摘要，不加载整部小说。导航源校验只读来源元信息；场景卡完整状态/原文/作者采纳仍由既有服务在修订前验证。投影只报告“来源版本改变”，不把导航状态当作完整一致性检查。候选/原文/历史均保持原身份。

SQLite及作品包v9，v8升级前一致备份，v1—v8补空结构工作区。当前/历史的线程、场景、章节、提醒目标ID重映射；缺少的历史目标保留为失效链接；伪造跨作品关联原子拒绝。导航投影不加入poll，仅按需查询当前页/作者设置/历史。不携带模型配置、密钥或检查缓存。

真实SQLite/HTTP/Electron验证五视图、来源/候选区别、线程保存/归档/历史、提醒忽略与版本改变、跨作品拒绝、重复文字/别名、单章与场景待审回写范围。5000章基准验证分页与无全文响应，记录响应体积/耗时/匹配范围；不替代文学质量评测。完整旧回归及四组已有基准复验，最终合入本地main。
