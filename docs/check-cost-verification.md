## 实现

- SQLite派生checkCache表，保持作者数据及作品包v8，缓存不进入作品/恢复包或poll。每作品最多256条，每条512KB；旧应用忽略此表，删除后重新检查即可。
- 键包含实际原文窗口及版本、项目、作者要求、目标章/检查用途、完整规则/验证协议版本、模型配置及修订、输出规格、状态与文风摘要。只有完整且有效的结果缓存；命中仍解析验证证据。Task初检与独立复核作为一组，Writing逐章与跨章复核各自独立，不能互相代替。
- 重新检查枚举全部窗口；来源版本、规则、模型或要求变化则重新检查依赖窗口，其余窗口复用。每章版本变化保守失效该章涉及的窗口，未做缺乏证据支持的语义跳过。缓存失败/取消/预算不足/陈旧来源/重大变更不成为通过结果。
- 任务保存复用/新检查窗口数、覆盖进度与原文疑点；缓存命中不增加请求或虚构Token节省，历史用量不清零。Task旧路径在模型不报告用量时保留完整输入/输出调用预留，不能以短回复低估消耗。
- 疑点按类别、连续写作回改目标及来源版本/逐字证据集合去重，理由措辞不影响身份；新证据或版本保留。作者已处理或忽略的旧问题保持其状态。
- 作者选择“快速试写”时只生成一个没有正文的新章，保存草稿并等待作者，明确“尚未一致性检查”。点击“继续认真定稿”沿用同任务、预算与用量执行剩余检查；手改稿保持，重启/导入不自动调用。默认认真定稿保留原流程。

## 固定样本对照

`npm run --silent benchmark:check-cost`运行真实TaskRunner、SQLite与本地HTTP，[JSON证据](research/2026-10-14-check-cost-benchmark.json)。模型响应由固定标签的fixture提供，用于验证冷热结果、来源变化、完整覆盖及成本协议。

| 样本 | 冷检查 | 相同来源重复 | 来源改变 | 疑点结果 |
|---|---|---|---|---|
| 同日年龄冲突 | 2请求，1321 fixture Token | 0请求，复用1窗 | 消除冲突后2请求，1057 Token | 1→1→0 |
| 有解释的物品取放 | 2请求，1063 Token | 0请求，复用1窗 | 尾部改变后2请求，1071 Token | 0→0→0 |
| 不同零件/对象 | 2请求，1061 Token | 0请求，复用1窗 | 尾部改变后2请求，1069 Token | 0→0→0 |
| 四章12窗口 | 24请求，208198 Token | 0请求，复用12窗 | 末章改变后8请求，65240 Token；复用8窗、重查4窗 | 0→0→0，全12窗覆盖 |

缓存命中本轮零调用，不代表历史账单为零。输入/Token为固定fixture报告，不是服务商分词或账单。fixture按标签返回冲突，不能用其0漏报/误报宣称真实AI检查质量；`realModelMissRate`、`realModelFalsePositiveRate`、`authorAcceptance`、`providerBill`均为null。真实长篇20—30章、跨窗矛盾及费用仍需单独验收。

文风/场景固定200、2500、3000字各条件仍4次默认请求；[文风复验](research/2026-10-14-check-cost-voice-regression.json)、[场景复验](research/2026-10-14-check-cost-scene-regression.json)与[召回复验](research/2026-10-14-check-cost-recall-regression.json)保留独立报告。

## 独立审查及交付

一次只读审查固定范围`97bbcc2..1232eb0`，无Critical，报告2项Important及1项Minor。最后一项会使已经忽略的疑点再次出现，按其作者操作影响提升为Important，一并红绿修复，未另发复审：

1. 带问题的Writing缓存序列化了派生chapterId，严格解析器拒绝命中：缓存只存模型协议字段，读取时从验证证据重新推导目标章。逐章及跨章的非空结果各有失败→通过回归。
2. 作者要求改变后旧进度跳过先前窗口：逐章、跨章及完成检查使用同一完整依赖指纹，涵盖规则/协议、实际来源、作者要求、模型配置及状态/文风摘要；先前窗口重新进入检查，仍相同的缓存才可复用。补作者要求和模型变化两项失败→通过回归，正文/历史用量保持。
3. 证据按多重集合判身份，重复引文会让旧疑点再建档：按唯一证据集合识别，保留作者已忽略状态；重复引文回归失败→通过。

审查未判断的真实模型质量/账单保持缺测；完整桌面与文档由主执行者完成；无关旧实现和历史截图未纳入变更。5项新增修复回归及583项全套服务、类型与构建通过，最终59项完整桌面和四组基准全部通过。
