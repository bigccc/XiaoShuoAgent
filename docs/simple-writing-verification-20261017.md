# 简化写作与审核验证记录

2026-10-17。依据 `simple-writing-design.md` 中用户确认的六项选择实施。

## 实现结果

- 默认写作只填章数、每章字数与可选要求，不要求填写 Token 或选择快速/认真模式。每次任务保存目标字数，允许 ±10%。
- 主进程按章数、目标字数与上下文估算本次额度。旧显式预算仍受限；自动任务点击继续后安排剩余工作，已有用量不清零，不自动无限续费。
- 文风/节奏建议不触发反复改写，不阻止任务完成。模型报告的字数意见不代替程序计数；检查已有正文时保持原有篇幅。
- 引用无法核实的疑点保留为未证实建议，不据此修改正文，也不声称这些疑点已经排除。未知结构或含义不明的重大变更仍属于处理失败，不能伪造成功。
- 真实冲突与重大创作决定保留暂停机制，并提供保留前文/设定、修正新稿的可执行入口。
- 已有正文在当前任务内展示差异，采用后继续。过期方案不能采用，可以放弃并重查；历史版本保留。
- 状态与伏笔可在完成检查后自动供后续批次参考，保留来源并标为自动整理。伏笔回收可自动绑定有效的埋设与回收双证据；没有依据时不标记已回收。
- 来源过期、拒绝或重新核对后，不让更早的状态冒充当前状态；同章多次生成优先选择新来源版本。

服务测试使用真实 SQLite 与本地可控模型接口；桌面测试使用 Electron 的真实 IPC，在独立临时数据目录运行，不读取或写入用户作品数据库。

主要覆盖：不填写 Token 的多章写作、±10% 自动调整、多个章节一次续跑、保留作者编辑、旧任务显式预算、取消/重启恢复、已有正文差异采纳、过期方案重查、主观建议与未证实疑点、状态跨批次参考、来源变更及拒绝、伏笔双证据。

只读审查提出的恢复和来源选择问题已修复，并增加先失败后通过的回归用例。多章续跑还区分了系统的依赖失效标记与作者实质修改，避免把未被作者改动的新稿误认成不可自动修正的旧稿。
