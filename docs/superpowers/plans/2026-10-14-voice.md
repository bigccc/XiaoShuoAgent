# 文风与角色声音 Implementation Plan

> **For agentic workers:** Use the previously accepted native implementation method, task-by-task TDD, then one fresh independent review. Steps use checkbox syntax.

**Goal:** 交付作者选择/认可样本、可审阅撤销的叙述文风与角色语言卡，并安全用于创作。

**Architecture:** voiceRecords/voiceJobs独立表与按需IPC；候选/采纳快照、原文证明及历史复用前阶段模式。voice-context提供有界表达元信息和摘要，创作原文documents及回写权限不扩大。

**Tech Stack:** Electron、React、TypeScript、SQLite、ChatProvider、Vitest、Playwright。

**Spec:** `docs/voice-design.md`。

## Global Constraints

- 第四阶段范围，1—6样本、每处4000/合计12000字符；9个字段每项400，历史50版，分页40。
- 样本明确认可、来源正文确认后提取/采纳；候选不自动启用，未采纳编辑保留原采纳快照。
- 无默认学习调用；显式提取100000默认/1000000最大Token、4000输出、1次尝试，重启手动继续。
- 创作表达参考≤8000字符且≤窗口四分之一，1份叙述/4份匹配角色，非原文/事实/全文许可；并发变化阻止回写。
- v8升级前备份、旧包归一化、引用重映射；不修改生产作品、不付费评测、不安装/推送/发布。

## Review Focus

- 重复quote、异作品、未认可样本、实体归档/改变、接受快照与历史：Task1真实保存/包验证。
- 模型请求中编辑档案/认可/正文，预算未知与重启/导入手动继续：Task2 HTTP验证。
- 无档案变启用、待审编辑不改变原采纳、角色匹配/字段体积、不把规则quote当原文：Task3上下文验证。
- 定向候选旧摘要、不同范围续跑后旧候选采纳、导入有效/失效摘要：Task3持久改稿及包验证。
- 作者认可动作、脏表单/关闭重开、归档找回、历史与窄屏：Task4桌面验证。
