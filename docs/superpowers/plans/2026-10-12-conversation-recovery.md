# 创作回复恢复实施计划

依据：作者已批准空响应重试、格式恢复、减少单轮输出负担、可见恢复状态和诊断记录。沿用现有工作区，保留此前未提交改动。

## 约束

- 对话回复获取与修复链路最多三次 HTTP 请求，共享次数和四分钟总时限；空响应最多重取一次，格式最多修复一次。Provider 内层重试在此关闭。已有阶段辅助整理任务使用其独立记录与重试流程。
- 空响应只指正常完成但无 content 的响应；思考文本不当正文，拒绝/工具调用不当空响应重试。
- 每次请求保留用量、结束原因、正文长度和原始 content；不记录凭据、HTTP 原始错误或思考正文。未知用量显式标记。
- 格式修复使用完整原始 content，不能只取第一个 JSON；已返回的文本值不得被修复调用删改。重新执行全部授权、来源版本和完整性检查后才能落库。
- 取消、响应截断、达到输出上限不自动写入；已生成片段可按需查看。

## 步骤

1. 在 `tests/conversation.test.ts`、`tests/provider.test.ts` 添加故障回归，先看到失败：空响应后成功、连续空响应、JSON 后额外字段、格式恢复失败/内容丢失、恢复后越权、恢复中取消、合计用量与未知用量。
2. `src/main/provider.ts` 增加安全诊断和单次请求选项；保留终止失败的 usage/partial，区分空响应与截断。
3. 新建 `src/main/conversation-response.ts` 集中恢复循环；`src/shared/types.ts` 和 `src/shared/conversation.ts` 增加可选恢复记录并验证，保持旧记录兼容。`src/main/conversation.ts` 接入，错误和取消仍保存记录。
4. 按创作阶段精简系统输出契约；历史 assistant 回复保持 JSON 形状。正文优先，辅助资料只返回必要变化，不要求每轮重建全部资料。
5. 会话 UI 显示恢复阶段、调用数、合计用量、未知用量提示；新增按需详情读取，普通轮询在 SQLite 中剔除原始回复，避免反复传输正文。
6. 验证持久化/作品包/取消/授权/来源冲突及 Electron UI；进行一次独立代码审查。构建本地 arm64 安装包，单独记录安装包验证结果，不直接替换正在使用的应用。

## 重点边界

- 失败恢复不能静默清空 chapters/notes 或覆写作者在等待期间的手改。
- 网络重试和格式修复共享次数，取消必须中止等待和请求。
- 未知用量不计为零；服务端已报告的失败用量须计入本轮。
- 只读详情和备份包含原始失败记录，工作区快照不包含大段原始内容。
- 完整流式终止标记没有末尾空行时仍应识别；真正截断仍失败。
