# 小说工坊优化路线图

2026-10-13。用户选择：全量计划，先实施第一阶段（质量基线＋远章召回）。依据：[调研比较](research/2026-10-13-product-comparison.md)。

## 产品约束

保留「定故事 → 做准备 → 开始写」三步创作、作者审阅、来源版本保护、历史和恢复。新增能力后台运行、按需展开。已确认正文与计划、未采纳候选分开。每阶段交付工作代码、回归测试、证据与限制；测试、真实模型质量、安装版验证分开记录。

## 分阶段交付

| 阶段 | 交付 | 依赖 | 验收与完成标准 | 本轮状态 |
|---|---|---|---|---|
| 1：基线与远章召回 | 本地关键词/人物名称召回、版本化原文片段、对话与连续写作接入、可展开出处、固定基准 | 现有章节、资料和来源保护 | 远章命中；排除其他作品、未来章、未确认草稿；源编辑后重新取原文；片段不能取得全文覆盖权限；总上下文有界；重启/备份兼容 | 已完成，详见[验证记录](context-recall-verification.md) |
| 2：故事状态 | 事件、知情、物品、伏笔生命周期；提取候选、作者确认、源版本失效；人物卡/伏笔列表 | 阶段1来源与基线 | 区分计划/猜测/谎言/事实；正常状态迁移不误报；撤销/恢复与备份完整；同批临时状态不变成稳定事实 | 后续计划 |
| 3：场景写作 | 2—4张可编辑场景卡、目标/阻力/转折/视角/篇幅/钩子、定向修订 | 阶段1基线；关联状态使用阶段2 | 200字及2000—3000字样本对比；不增加强制确认；段外不变；重大方向变更暂停；篇幅、采纳率和成本一并比较 | 后续计划 |
| 4：文风与角色声音 | 作者认可样本、文风卡、角色语言卡、查看/编辑/撤销 | 阶段1来源；阶段3生成输入 | 作者控制样本；陈旧样本不自动注入；盲评角色辨识、叙述稳定和实际修改量 | 后续计划 |
| 5：检查与成本 | 版本/规则/配置缓存、依赖局部复核、疑点去重、快速试写/认真定稿 | 阶段1指标；阶段2依赖关系 | 保持或降低漏检/误报再谈节省；重启不清用量；未知用量不是零；更换规则/模型使缓存失效 | 后续计划 |
| 6：结构导航 | 场景/主支线/人物出场/视角/伏笔视图，明确问题型修订入口 | 阶段2、3实体与阶段4人物卡 | 导航大作品仍按需加载；提醒可解释、可忽略；窄屏可用；不用工作流画布替代主流程 | 后续计划 |

## 后续阶段的模块边界

- 阶段2：`src/shared/story-state.ts` 定义状态/证据/候选；`src/main/story-state.ts` 管理依赖与确认；`src/renderer/story-state.tsx` 提供列表。复用现有 Store、DomainService 与作品包迁移，新增格式前安排迁移前备份与旧包回归。
- 阶段3：`src/shared/scenes.ts` 定义章内场景计划；`src/main/scene-writing.ts` 控制计划/定向修订；`src/renderer/scenes.tsx` 供按需编辑。每个场景持有稳定 ID 与版本，正文仍以章节为作者采纳单位。
- 阶段4：`src/shared/voice.ts` 与 `src/main/voice.ts` 维护经作者认可的样本和派生档案；在故事资料页管理，候选和失效状态与阶段2一致。
- 阶段5：`src/main/check-cache.ts` 管理范围、源哈希、规则版本、模型配置和结果的缓存键；增加质量/成本对比而不是单看缓存命中。
- 阶段6：基于上述实体提供投影和查询，目录与正文继续按需读取；具体接口在前序阶段实际验收后编写详细实施计划，避免预先锁定未验证结构。

## 质量门槛

固定自有样本，记录模型/提示词版本、目标篇幅、事实冲突与无冲突对照、来源覆盖、调用/Token/耗时、作者采纳字数和盲评。首阶段基准只证明原文召回和保护行为；正常20—30章文学质量、价格账单和实体安装验收单独开展并记录，不能用检索命中率替代。

开发采用本地隔离工作区，保留原目录调研与视频内容。本轮不包含发布、生产作品修改、安装应用替换或新增付费模型评测。
