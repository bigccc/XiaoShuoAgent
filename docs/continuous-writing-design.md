# 连续写作 Agent 设计

2026-10-12，用户在 grill-me 中确认全部建议，并要求继续执行。

2026-10-17 更新：默认体验以 [简化写作与审核](simple-writing-design.md) 为准。普通入口只提供章数、字数与额外要求；系统自动安排调用额度，文风建议不再触发反复重写或作者待办。以下保留持久任务与版本保护的设计依据。

## 目标与边界

第一阶段建立可复用的持久任务执行能力，以“写完前五章”为验收场景。根据作品现有进度补齐到第5章；“接着写五章”表示在已有章节后新增五章。普通单轮讨论、试写、改稿继续沿用原入口。自然语言变体不得因数量正则漏匹配而静默降为一章。

任务自动准备必要的写作计划、逐章生成并保存、检查篇幅与一致性、最多两轮修订，最后对目标章节做跨章复核。已有非空正文不直接改写，需要修改时生成待审稿。任务新生成的正文可自动修订并保留历史。普通情节自行补全；推翻既有人设、主线、结局时暂停询问。

两轮修订后，明确且影响后文的事实冲突可继续有限定点修正，仍无法解决才暂停；文风等局部建议收起展示，不反复重写、不阻止任务完成。篇幅允许 ±10%，自动调整后仍未达标时保存进度并提供继续完成，不包装成创作决策。无法核实引用的疑点保留为未证实建议，不据此改稿；未知协议结构、含义不明的重大变更仍不能当成检查完成。

## 技术方案

在 Electron 主进程内使用 LangGraph JS 的 StateGraph，节点为规划、写作、检查、修订、跨章复核与结束。复用 ChatProvider、DomainService 的版本保存、现有原文证据校验和待审稿机制。模型仍直连用户配置的接口，不引入云端 Agent 服务或 Python。

由应用 SQLite 中的任务状态负责持久化与恢复，LangGraph 负责流程路由；这是应用级阶段恢复，不宣称原生 graph checkpoint。每个业务提交和步骤推进在同一事务内完成，已提交章节不重复创建。暂停、取消、失败和重启保留成果；重启不自动发起付费调用，用户续跑才继续。

所有模型调用，包括规划、检查、修订、重试，使用同一任务额度。新任务按章数、字数与前文自动估算；旧任务及显式指定的 Token 上限仍受约束。异常停止后，用户点击继续才为剩余工作安排额度，已有消耗不清零；未知用量保留预留值，不按零扣减。额度是调用约束，不是价格保证。

模型请求携带版本化原文，生成期间作者修改正文、资料或规划时，不用过期回复覆盖当前数据。规划尊重现有资料，任务补充计划不静默改动作者已确认的设定。

## 体验与验收

对话中显示目标范围、当前阶段、已保存和已检查数量；技术用量收起。已有正文的修改在当前任务展示差异，点击采用后继续；旧版本可恢复。自动整理的场景、状态与伏笔保留出处，检查完成后可供后续批次参考；不会伪称作者已确认，来源改变或拒绝后失效。不会因图节点成功返回就称任务已完成。

验收包括空书生成前五章、已有两章补齐到第五章、不同自然语言表达、否定/讨论不触发执行、章节顺序和空章、字数修订、硬冲突暂停/软问题继续、两轮上限、预算、取消、作者并发修改、重启续跑、备份导入。使用真实 SQLite、loopback HTTP 和 Electron 回归；付费模型效果及安装应用验收分别记录。
