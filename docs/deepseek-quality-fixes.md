# 真实 LLM 质量问题修复与复验

日期：2026-10-07。针对上一轮发现的四项问题，已完成代码修复、真实 DeepSeek 复验和新版安装包验证。**明确对照和已修订样章通过；复杂原文仍需要作者判断，不宣称模型永不误报、漏报或达到文学质量交付标准。**

## 已落地的行为

| 问题 | 当前行为 |
| --- | --- |
| 把通过意见当成问题 | 检查提示只允许确定的互斥事实；每次初检后都独立复核原文，包括初检空结果。初检和复核差异保留在任务记录中，不将原始通过项直接入库 |
| 漏掉物品状态、年龄等矛盾 | 检查专用配置改为官方 `deepseek-v4-pro` 思考模式，低思考强度；重点检查同一人物、时点、物品位置和动作前后状态 |
| 引文存在但不相关，或复制格式失败 | 独立复核选择矛盾双方的相关原文；来源ID和版本仍严格校验。仅空白差异且能唯一定位时还原成真实原文；改词、改标点、错误来源、错误版本、歧义匹配均拒绝。JSON或引文不合格最多修正一次，不能靠清空问题掩盖失败 |
| 字数大幅偏离 | 右侧新增“本次章节字数”；正文按非空白字符计数、不含首行章节标题，允许目标±20%。超出时最多修订两次，原候选与每份修订版本都保留。仍不合格或预算不足时暂停，作者正文不自动替换或确认 |

规划和正文继续使用 `deepseek-flash` 非思考模式。Pro检查每次请求输出预算最多8000 Token，包含思考和最终JSON；剩余可用预算低于4000时先暂停。初检、独立复核、格式修正、字数修订都计入同一任务调用与用量。思考正文不进入小说候选或任务片段。检查比原Flash配置消耗更多Token；Pro服务单价也更高，实际费用以账单为准。[官方模型价格](https://api-docs.deepseek.com/quick_start/pricing/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[JSON输出](https://api-docs.deepseek.com/guides/json_mode/)。

新界面生成任务明确记录本次字数；旧任务没有该字段时保留旧策略，避免重解释已保存请求。新增阶段、次数和目标均通过严格作品包校验，损坏包不会部分导入。

最后修稿是验收样章中的作者操作，历史候选保留。没有把AI输出自动确认，也没有删除之前失败、误判或有疑点的任务。

## 必须保留的限制与失败证据

- 原始“三章干净样例”标签并不表示已人工保证完全无歧义。Pro思考检查提出六把椅子与到场人数的推断性疑点；另一次达到输出上限而失败。它不作为明确无冲突的评测金标准，原文和结果全部保留。
- Flash与Pro非思考模式的重复检查均出现过误判或漏检，因此没有仅靠一次成功宣称质量通过。当前选择Pro思考并保留双重检查、失败拒绝和作者复核。
- 大量推理也可能耗尽输出或总预算。失败会保留候选／片段和原因，不转换成“无问题”。语义相关性仍由模型和作者判断，原文匹配校验不能证明推理正确。
- 未进行20章约3000字的长篇阅读、Intel实体机运行、最低系统设备、跨实体Mac迁移或签名公证；这些不由本轮结果代替。
