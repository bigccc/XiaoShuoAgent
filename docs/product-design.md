# 网文创作系统设计访谈

状态：2026-10-06 用户对 Q18 回复「OK」，完整范围及默认方案已确认。首版本地实现和内部测试包已完成，外部验收边界见 `docs/verification.md`。

## 用户提出的目标

创建小说名称与大致故事背景，组织故事线、大纲、人物、场景和世界设定，再由 AI 生成详细正文；支持多种风格以及提取爆款网络梗。

## 已确认决策

2026-10-06，用户回复「4 ABC，5C，其他按你的建议」后确认：

1. 首版服务个人创作流程。随后用户补充需要打包成 App 并可分发给其他电脑；团队协作、对外收费仍不是已确认的首版目标。
2. 采用半自动创作：AI 提出设定和大纲，作者确认后按章生成。日常描写可自主发挥，重大剧情与设定变更需作者确认。
3. 先验证连续二十章的可读性及人物、情节一致性，再扩展题材和长度。第二轮已接受测试样例：都市轻喜剧、每章约 3,000 字、全书目标 30 万字；字数目标可调整，二十章不是作品长度上限。
4. 题材、文风、叙事节奏分别配置，允许组合。用户选择 A/B/C，未将参考文本风格提取纳入本轮确认范围。
5. 同时支持网络表达素材与剧情套路素材。
6. 首版素材流程为：作者提供材料，系统提取并解释，保存到素材库，创作时按需选用。主动上网发现素材不是当前确认的首版流程。
7. 素材应用需要考虑故事时代与人物身份，避免生硬使用。

第二轮用户回复「主要在 Mac OS 上使用。最好是能打包成 APP 可以发布给其他的电脑使用。其他的按建议」，进一步确认：

8. 产品主要在 macOS 使用，需形成可安装、可分发到其他电脑的 App。此前建议的仅在浏览器内使用的本地工作台形态由此调整；第三轮确认首版只支持 Mac，覆盖 Apple 芯片与 Intel。打包分发是产品要求，不代表已授权公开发布。
9. 准备流程为：创意与看点 → 核心人物及世界设定 → 主线与支线 → 全书／分卷大纲 → 近期章纲。AI 先提出方案，作者可修改、补充、重做或返回前一步。
10. 默认逐章生成，允许作者明确指定连续生成 3—5 章。生成正文先保存为草稿；发现重大剧情变更或设定冲突时暂停，交给作者处理。
11. 修改设定后列出受影响的设定、章纲和章节，提出修改方案。已确认正文不直接覆盖，由作者选择修改；重写保留旧版本，支持比较和恢复。
12. 作品级默认题材、文风和叙事节奏；章节可调整局部语气与节奏，同时保持人物说话方式与整体叙述习惯连贯。
13. 首版素材输入支持粘贴文字、上传 TXT／Word，并保存来源备注；网页链接解析后续扩展。提取结果先由作者检查，再入库；剧情规划时推荐适用素材，由作者选用或明确授权 AI 自行选用。
14. 作品本地保存，通过模型 API 生成内容；第三轮确认由每位使用者配置自己的模型服务。

第三轮用户回复「按你的建议来」，确认 Q13—Q17：

15. 首版只支持 macOS，覆盖 Apple 芯片与 Intel Mac，分别验证安装包；Windows 后续扩展。使用者安装后直接打开，无需配置开发环境。
16. 每位使用者自行配置模型 API 地址、密钥和模型名称。支持多个配置，为规划、正文、检查分别选择模型，也可使用同一个模型。
17. 长篇一致性检查覆盖人物与关系、时间线、地点、世界规则、角色知情范围、伏笔进展。结果提供原文依据与原因，由作者判断处理；AI 检查不作为绝对正确的判定。
18. 同批次后续章节允许参考前面的草稿，整批仍需审阅；修改前章后，相关后续草稿标记为需要复核。
19. 中断保留已完成章节与未完成片段，由作者选择继续或重写。网络临时错误最多自动重试两次，质量问题不无限自动重写。
20. 显示调用次数及服务商返回的用量，单次任务可设置用量上限。
21. 正文导出 TXT／Word；完整作品备份包含设定、大纲、正文版本和引用素材，可在另一台电脑导入。
22. 本地自动保存并保留定期备份，API 密钥不进入作品备份。
