## 修复的兼容问题

旧适配器不设置 thinking。DeepSeek 当前默认思考模式可先消耗输出预算，正文生成后的检查只允许1500输出Token，真实调用两次在检查阶段达到长度上限且没有最终正文。

在保存的同一候选上下文上做一次独立对照（非流式诊断）：默认模式 HTTP200、finish=length、content=0字符、reasoning_tokens=1500；关闭思考模式后 HTTP200、finish=stop、1318输出Token，返回可解析检查JSON。诊断重建了生产上下文与系统提示，未向日志输出鉴权头或思考正文。

修复仅对域名严格等于 `api.deepseek.com`、模型为 `deepseek-flash` 或 `deepseek-v4-pro` 的请求加 `thinking: { type: "disabled" }`。没有扩大预算、放宽JSON或来源证据验证；第三方接口、相似域名和其他模型不注入该参数。若作者需要思考模式，当前版本没有可切换的配置项。

参考：[官方模型和接口说明](https://api-docs.deepseek.com/quick_start/pricing/)、[官方思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 未通过的质量项

1. **误报导致暂停。** 连续第2章检查返回6项，其中包含“暂无不一致”“不构成场景转移”“符合”“未见知识越界”等明确通过意见；第3章也有4项类似提示。它们被放入 `issues`，应用按安全规则暂停，未偷偷过滤掉。后续需要强化问题输出契约，并用真实干净／冲突样本成对回归。
2. **漏报与不稳定。** 雾港第一章写“把信纸折好，放回信封”后又写台上的信纸被风吹翻；恢复检查却返回空问题。独立诊断与恢复调用的判断差别很大。检测到植入的年龄冲突，不代表六类问题均能可靠发现。
3. **字数约束偏离。** 批量要求每章约250字，实际候选按字符串字符计660／366／369（含标题、标点和换行）；取消续写的第1章偏离明显。尚无稳定的目标字数闭环验收。
4. **引用真实不等于引用相关。** 年龄冲突结果包含“他拆开。”这一真实但无助于证明年龄冲突的引文；来源逐字校验只能保证引用存在，不能保证推理质量。

本次没有进行连续20章、每章约3000字的长篇人工阅读；也没有对 Pro 模型、Anthropic 协议、最低macOS版本、Intel实体机、两台实体Mac迁移或签名公证做新验收。
