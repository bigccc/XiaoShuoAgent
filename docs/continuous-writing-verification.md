# 连续写作 Agent 验证记录

日期：2026-10-12（Asia/Shanghai）。本轮基于当前工作树实现，保留所有已有未提交内容；没有 Git 提交、推送或替换 `/Applications` 中的应用。

## 已实现的行为

- LangGraph JS 1.4.21 在主进程组织规划、生成、检查、修订和跨章复核，继续使用原 ChatProvider、SQLite 和版本保存接口。
- “写完前五章”“帮我把前五章都写完”等请求补齐到目标章；“接着写五章”表示新增五章。无法明确解析的多章执行请求提示范围，不静默降成一章。
- 每章最多两轮自动修订。影响后文的事实冲突暂停；局部文风、篇幅问题标记待审并继续，最终不标为全部通过。
- 已有正文只产生待审稿；任务新稿经作者手改后也转为待审保护。正文、笔记或规划变化后拒绝采纳陈旧候选。
- 任务步骤与正文在同一事务提交；逐章检查与最终复核均保存窗口位置和来源摘要，源变化时重新检查失效部分。重启不自动调用模型，续跑保留费用与已保存章节。
- 所有请求与重试共用预算；未知用量保留预留值，并显式提示。检查整理最多一次，不能删改疑点含义或清空问题来得到通过。
- 支持模型偶发返回的精确 `type=json_object/content` 外壳，逐字保留内层正文；外壳包含额外决策字段时拒绝展开。控制字段类型不明、重大变更理由不明确时停止。
- 数据库和作品包升级 v5，迁移前备份；旧包兼容、引用重映射、跨作品校验和 IPC 长字段裁剪已覆盖。
