# 第一阶段：质量基线与远章原文召回

2026-10-13；范围经用户选择确认。依据：[优化路线图](optimization-roadmap.md)。

## 数据与流程

使用当前章全文、作者指示和任务计划中的关键词，以及有效人物/地点资料的名称和「别名」行作为搜索线索。只取同作品、当前故事位置之前、已确认且无需复核的章节；已选目标章和近期正文不重复加入。每次从当前快照计算，没有持久摘要/索引，所以源版本变化后旧片段不会复用。单章返回有界候选中词条覆盖最高的一处片段，最多6章，每处最多480个UTF-16字符，总片段不超过2880字符；记录章节ID、revision、ordinal、标题、start/end、逐字excerpt与命中词。首阶段不是语义搜索，不保证找出所有相关事实。

接口 `recallPassages(state, projectId, { query, beforeOrdinal, excludeChapterIds })` 返回 `RecallReference[]`。词条最多24个，每个2—40字符；中文使用Intl.Segmenter加人物名称/别名，过滤常见操作词。排序按不同词条命中权重，每词最多选16次早期匹配与末次匹配作为候选锚点，并对窗口内实际词条覆盖评分；平分时较近章节优先，最终按分数/章号/ID稳定排序。

## 创作接入

- 对话：原目标全文先加入，再从余量中预留不超过20%的窗口给相关旧章片段，余量用于阶段资料/笔记；只有真正写入提示词的完整片段记入 `contextReferences`。旧章片段不加入 `full`，不能授权模型覆盖旧章。近期参考章同样遵守当前故事位置，明确授权的目标章仍按原规则读取。
- 连续写作：生成/修订时从作者目标、逐章计划和当前章提取查询；单章检查也纳入同一批相关旧章证据。空目标时也遵守当前章边界；直接来源为当前/未来章的笔记不混入历史事实。最终复核只检查任务目标范围，保留原范围声明。`ContextDocument.reference` 表示部分原文；`boundContext` 先保护要求完整的目标全文，再给其他资料与片段分配余量。真正发送的片段在请求尝试时与调用次数一起记录到任务 `contextReferences`，`contextReferenceCall` 记录请求序号、阶段和章号；预算不足或密钥失败不建立新的实际参考记录。
- 原文更改或来源版本不符：沿用现有过期结果保护。引用片段不扩大改稿授权。不存在有意义关键词或窗口不够时不加入片段，保留原创作流程。

## 作者体验与兼容

聊天与任务中显示折叠的「本次参考的远章原文」，包含章号、标题、命中词和逐字片段；来源已改或已移除明确提示。元数据来自当前章节目录，无需为每条引用拉取全文。首阶段作者可在指示中指定人物/物件，直接通过现有看稿搜索补充；独立的手选/排除资料控件留在第二阶段前细化。

`contextReferences` 为可选字段，旧作品/旧任务无字段继续读取。现有v5作品包直接保存并重映射引用与可选请求归属记录；校验最多6条、字段长度、来源与作品归属，允许已删除的历史来源保留为不可跳转的审计片段。无需新数据库表、迁移、API密钥或额外服务。

## 基准与验收

固定自有召回样本：远章钥匙转交、人物别名、多个相关历史、同词干扰、无相关原文、未来章、草稿、其他作品、失效资料、正文修改/恢复。基准分别记录原近期上下文与新增召回的命中、误召回、字符量与耗时；不将字符估算当作服务商Token用量。另测5000章/约1500万字符的数据扫描，记录环境和结果，不设置易抖动的墙钟通过阈值。

服务测试用真实SQLite与loopback HTTP观测实际提示词；校验旧片段不能覆盖整章、模型响应期间旧来源改变会阻止保存、重启/作品包引用有效。桌面回归验证出处、源变动提示、三步主流程和窄屏；本轮不向真实付费模型发送请求。
