# 第二阶段验证：故事状态与伏笔

2026-10-14（Asia/Shanghai；开发于10月13日开始）。用户授权「继续下一个阶段」，仅实施[路线图](optimization-roadmap.md)第二阶段。[设计](story-state-design.md)与[实施计划](superpowers/plans/2026-10-13-story-state.md)记录范围与约束。

## 已交付

- 独立状态记录支持事件、位置、伤势/能力、物品、知情、关系与伏笔；叙述性质区分事实、计划、猜测、谎言、回忆。
- 手动录入及AI提取均先产生候选；事实来源正文确认后才可采纳。待审编辑保留之前的采纳快照；最新依据失效阻断状态，不回退旧事实。按故事章节位置读取，早章不提前注入后章变化。
- 逐字原文、偏移、整章哈希、修订和章节位置保存；人物资料可绑定。原文改变或删除后须复核；旧引文仅唯一匹配时重绑，否则作者重选。保留编辑、拒绝、历史恢复及归档恢复。
- 伏笔计划、埋设、推进、回收与放弃分开；回收要求按顺序区分的双侧证据。同一人物关联的多条线索分别保留。
- 持久提取范围最多20章，每段16000字符、重叠300；默认100000、最多1000000 Token。请求前预留，未知用量保留预留值；候选和分段推进同事务，源变阻止旧回复入库。重启不自动调用，续跑保留已有进度和预算。
- 连续写作可用原响应附带最多20条状态候选，不增加状态提取请求。未经采纳的状态仅用于同批此前新稿；已有正文待审稿不提前记成事实。
- 创作最多参考20条状态的原文，元数据不会冒充原文。任务、对话与写作核对状态选择摘要，防止作者修改状态后旧回复覆盖当前稿件。
- 「故事资料 → 状态与伏笔」提供采纳状态、伏笔清单、原文定位、手动候选、历史、归档及提取进度。记录分页40条，历史按需读取；轮询不携带全部状态及历史，高级预算折叠。
- v6升级前备份，v1—v5作品包归一化为空新表。v6包重映射当前/采纳/历史证据与任务；跨作品、伪造当前引用、无证据的事实采纳快照拒绝且不部分导入。连接配置及密钥不进入作品包。

## 一次独立审查与统一修复

只读审查范围 `b81fa7d..be3e2a0`，未发现Critical，提出5项Important。统一修复前建立行为失败测试，再通过对应回归与全套检查；未再派第二次审查。

1. 最新回收章失效时旧埋设重新进入上下文：伏笔与普通状态统一先选故事位置上的最新记录，再判有效性，失效计入待复核。确认较早埋设的时间不覆盖较晚回收；早章查询仍可查看此前埋设。
2. 同人物不同线索合并：伏笔分组使用线索名称，人物仅作关联；复核人物资料保留线索名称。两个同人物线索均有独立原文上下文。
3. 导入身份重映射使有效任务摘要失效：导入前先判有效，完成所有重映射后只重建原本有效的摘要。用实际失败检查任务验证可续跑，原本失效的任务仍拒绝、零新增请求。
4. 导入提取任务缺少连接而无法继续：明确续跑时选本机检查连接（或指定连接），保留已完成章节、候选及已用预算。测试从已有候选和第2章继续，未重提第1章；导入本身零新增调用。
5. 归档后界面找不到：增加归档筛选与恢复；服务验证42条分页，桌面验证离开再回到页面找回历史及恢复。

Minor处理：单段提取无法证明回收双侧证据，保留严格校验，调整写作/提取契约为先提事件候选，作者在伏笔表单补双证据；核心状态选择、记录与提取服务展开为多行便于维护。React模板部分沿用紧凑写法，未进行无关风格重构。

完整桌面回归曾有1项旧安全接口清单断言失败，原因是新增两个受控只读接口尚未登记；更新明确的接口白名单后定向安全验收通过，仍验证Node不可读和第二窗口发送者被拒绝。未放宽IPC信任验证。
