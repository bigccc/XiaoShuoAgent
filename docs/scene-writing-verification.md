# 第三阶段验证：场景卡与定向修订

2026-10-14（Asia/Shanghai）。用户在第二阶段完成后授权「继续」。范围是[路线图](optimization-roadmap.md)第三阶段，[设计](scene-writing-design.md)及[实施计划](superpowers/plans/2026-10-14-scene-writing.md)记录合同。第四至六阶段仍待实施。

## 已实现能力

- 每章独立2—4张场景卡，含视角、目标、阻力、转折、信息揭示、篇幅与钩子；稳定ID、卡片修订和最多50个计划历史版本。篇幅合计须等于本章计划，增减卡片在界面明确说明重新分配。
- 场景计划是写作方向，保存不改正文或事实账本；原文、资料或所选故事状态改变会要求复核。作者计划不被模型附带卡片覆盖。
- 连续写作的默认卡片在同一次生成响应内准备，旧模型缺少可选卡片仍兼容；无效卡片警告、正文保留。额外场景信息有输入输出开销，不等于免费或更省费用。
- 显式规划是独立有预算的请求，保存来源和原计划版本，预算不足/取消/失败/重启保留原卡片；重启和导入不自动调用模型，明确继续才绑定本机连接。重大方向变更须提供作者决定后续跑。
- 定向修订只使用绑定原文，服务拼接原前缀/后缀，保留标题，进入已有待审稿；采纳之前正文不变。返回、续跑和采纳校验卡片、计划、原文、资料与故事状态。
- 在创作稿件或「看稿 → 正文与版本」按需展开「本章场景」；引用支持重复片段的明确位置选择。卡片未保存时保护导航；未发送修改要求和方向决定保存在本机草稿。来源版本可查看，专业预算折叠，poll不传卡片/历史/规划任务全文。
- SQLite及作品包v7；v6升级前备份，v1—v6兼容，计划/卡片/历史/任务/定向稿件引用重映射，模型配置和密钥不随作品包导出。

## 独立审查

一次只读审查固定范围 `4f08fb6..02640f6`，无Critical或Minor，提出4项Important。统一报告后一次修复，先失败后通过的真实行为回归覆盖如下；没有派第二次审查。

1. 导入场景候选可能越过选段改整章或标题：结构验证、导入与实际采纳共用前缀/后缀/标题不变量。重算校验和的伪造作品包原子拒绝；直接损坏SQLite候选也不能采纳。正常、已采纳历史保留兼容，旧帧超过50版被裁剪后已完成任务仍可只读导入。
2. 原始revision.start带sceneSource但selection不匹配卡片：创建、源复核、导入和采纳核对计划版本的卡片绑定与选段五个字段完全一致，其他片段不能取得这张卡的权限。
3. 本章计划字数被作品默认覆盖：SceneService统一提供章节有效目标；显式重建计划、生成wordLimit、长度检查和卡片捕获都使用作者保存的本章目标。测试2500字计划重建及不同于作品120字默认的200字生成，无多余篇幅修订。
4. 请求开始无计划，期间新建计划不能阻止旧回复：重新查询目标章计划，比较存在性、ID及revision；返回和事务提交两次核对。延迟HTTP测试保留作者新计划，旧回复不保存正文且任务暂停。
