# 小说工坊 · XiaoShuoAgent

个人网文创作桌面应用。作品、对话、设定、章节、版本、素材与任务保存在本机；规划、生成和检查使用作者自行配置的 OpenAI 兼容聊天 API。全新启动是空书架，没有预置小说或模拟 AI 输出。

## 使用与安装

要求 macOS 13.0 或更新版本（依据 Electron 44.5.1 的应用 Info.plist）。Apple Silicon 使用 arm64 包，Intel 使用 x64 包。将 DMG 中的 `XiaoShuoAgent.app` 拖到 Applications，或解压 ZIP 后复制应用。使用者无需安装 Node、Python或数据库。

当前本机构建没有 Developer ID 签名或 Apple 公证，不能当作已经通过 Gatekeeper 的正式公开发行版。Intel 安装与真实设备启动尚未验证；详见 [验证记录](docs/verification.md)。

1. 在书架新建作品，书名可留空。新书和旧书默认进入「创作对话」，说一个想法，或让 AI 推荐完整的故事概要。
2. 首次使用在「模型设置」添加自己的 API 地址、模型名称与密钥。对话默认使用正文模型，也可在输入框下方切换；密钥仅在主进程受系统保护，留空保留已有密钥。
3. 默认按「故事概要 → 必要设定 → 故事大纲 → 正文」推进。右侧显示当前阶段可编辑成果；概要包含转折和结局方向，大纲包含全书主线及近期 3—5 章。回复「继续／按推荐」整体确认后进入下一阶段；空白、待同步成果不会被自动确认。
4. 可说「后面的设定和大纲你来定」连续准备指定阶段，或说「先写一段看看」提前试写。提前试写保留规划进度，普通「继续」回到规划；「继续完成这一章」明确接续试写。进入正式正文阶段后，默认一轮一章，明确要求可连写最多五章。正文、设定、阶段成果都自动保存并保留历史。
5. 修改当前章或明确指定范围可直接执行；回改前文范围不明确时，先展示涉及章节，回复「一起改」或点击建议即可。运行期间的本机修改会阻止旧回复覆盖最新版本。
6. 对话、创作共识与当前稿件重启后保留；未发送输入在本机窗口中保留。可停止本轮、重试失败请求。完整有效回复才会自动应用；错误、截断、取消都不把半份 JSON 写成正文。
7. 顶部四个阶段标签可随时查看；切换标签本身不改变进度或确认状态。修改概要或设定后，下游成果标记待同步，AI 更新后集中确认；旧书补齐规划后仍可返回已有正文进度。「创作资料」随时查看 AI 整理的内容；「辅助工具」保留创意与风格、人物与世界、故事规划、正文与版本、检查、素材、任务审阅、导出和备份。
8. 辅助工具里的旧 AI 任务仍使用候选审阅流程。其批量生成、来源复核、素材审核和检查证据机制保持独立，不与对话自动保存混用。

对话会使用当前草稿作为上下文，默认总资料窗口为 48,000 字符，另纳入最多 12 轮、18,000 字符的近期对话及已保存共识。超限会显示阅读范围提醒，未完整纳入的旧章节、设定或阶段成果不能被模型整体覆盖。单份阶段成果最多 30,000 字符；过长的旧设定以明确标注的索引接续，原资料全文不裁剪。阶段状态作为作品可选字段随 SQLite v3 数据和作品包保存，旧作品无需额外迁移。每轮单次输出上限为 16,000 Token，多章范围为 32,000 Token，仍受模型自身限制；不会无限自动续写。对话中的情节判断由当前模型完成，独立、带原文证据的一致性检查仍在辅助工具中。

Token 用量标明服务商报告或估算／预算预留。预算是调用 Token 上限，不是精确费用上限。模型未配置时本机编辑、版本、导出和备份仍可用。素材与模型表单采用明确保存，离开有未保存修改时会提示保存、返回或放弃。任务审阅里的规划和每份提取素材同样保护修改，切换任务、导航或关闭都会先询问；规划必须明确选择采纳，素材的审核状态按作者勾选保留。


## 备份与数据

正常应用使用 Electron 的 `userData`，macOS 一般位于 `~/Library/Application Support/小说工坊`（已用未覆写的最终 arm64 应用实际确认）；数据库为 `works.sqlite`。**不要直接复制运行中的数据库主文件作为备份。** 在“导出与备份”选择完整作品包 `.novel`，再在另一台 Mac 导入为独立副本。模型配置表与明文／密文密钥不进入作品包；任务历史仍保留模型名称、接口地址等非密钥参数以便追溯，导入不会自动创建可用的模型配置，换机后需重新配置模型。

每 15 分钟内容变化时产生一致的自动恢复文件，`userData/recovery` 保留最近 20 份，关闭时也尝试保存恢复快照。恢复文件可以通过“导入作品／恢复备份”选择。自动恢复错误会显示在界面；重要迁移前请另存手动作品包。TXT 为 UTF-8，Word 导出为真正的 DOCX。使用过创作对话的作品默认包含当前草稿；其他作品沿用仅已确认章节的默认值，导出前可切换。数据库首次升级到 v3 前自动创建一致的 before-v3 SQLite 备份；作品包与恢复包为 v3，携带关联、同步任务、批次及归档历史，继续接受 v1／v2。导入副本重映射关联 ID。

概要对应书名、题材、简介与背景；设定对应人物、世界、地点、文风与节奏；大纲对应主线、全书大纲与近期章纲。全文编辑先保存本机草稿，停笔 5 秒后整理；辅助工具修改直接更新已关联阶段，不额外调用模型。未分类内容保留为补充说明。待同步、失败或冲突会阻止推进、正文生成及检查；可重试、取消或选择实际冲突中的版本。历史恢复同时恢复关联资料，涉及后续独立修改时先显示差异。移除只归档该阶段管理且没有其他引用的记录，不自动删除独立手工资料。字数目标保持作者设置，前期计划不会写成已发生的时间线或角色知情事实。

密钥由 Electron `safeStorage` 在主进程通过 macOS Keychain 保护，只在实际保存或使用凭据时检查和访问，不在离线启动时调用可阻塞的可用性检查；运行时不可用时拒绝保存非空密钥，并保留本机创作能力。不能从界面读回密钥。正式发行需要一致签名并验证升级后的钥匙串访问。

## 开发

开发要求 Node.js 22.13+，本机已验证 Node 22.22.1 / npm 10.9.4。依赖版本写死并由 `package-lock.json` 锁定，无需修改全局工具。

```sh
npm ci
npm run dev         # Electron + renderer 热更新
npm run build       # out/main、out/preload、out/renderer
npm start           # 启动构建结果
npm run typecheck
npm test            # 真实 SQLite / loopback HTTP 服务层测试
npm run e2e         # 构建并运行真实 Electron 控件工作流
npm run package     # 当前架构 .app
npm run make:arm64   # Forge .app + ZIP + DMG
npm run make:x64
```

开发主进程和界面职责分离；只经 `window.novel.invoke(command)` 与 `snapshot()` 调用受控 AppServices。主进程验证发送者主框架及 URL，禁用 Node 集成、启用隔离与沙箱；无任意路径或凭据读取接口。SQLite 使用 Electron 内置 `node:sqlite`，不需要原生数据库重建。

E2E 仅在独立临时目录运行，HTTP 仅访问当前测试创建的 loopback fixture，不调用外部付费模型。`NOVEL_TEST=1` 配合绝对 `NOVEL_DATA_DIR` 可显式选择测试数据目录；正常打包应用忽略该覆盖，测试不替换真实作品。测试通过主进程对原生文件选择框的边界注入所选临时文件，所有后续解析／持久化／导出仍走真实 AppServices。

打包结果在 `release/`；Forge 自定义 DMG maker 仅调用系统 `hdiutil`，没有额外安装工具。可选 `MAC_SIGN_IDENTITY` 启用签名，`APPLE_NOTARIZATION_PROFILE` 选择已有 notarytool keychain profile。签名／公证须由持证者配置，项目不含 Apple 或模型凭据；本次未使用这些变量。

对真实 arm64 包运行同一组验收：

```sh
NOVEL_PACKAGED_EXECUTABLE="$PWD/release/XiaoShuoAgent-darwin-arm64/XiaoShuoAgent.app/Contents/MacOS/XiaoShuoAgent" npx playwright test
```

打包、自动测试、真实 API、长篇阅读、两架构设备安装与签名公证的状态分别见 [docs/verification.md](docs/verification.md)。
