# 小说工坊 · XiaoShuoAgent

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

个人网文创作桌面应用。作品、对话、设定、章节、版本、素材与任务保存在本机；规划、生成和检查使用作者自行配置的 OpenAI 兼容聊天 API。全新启动是空书架，没有预置小说或模拟 AI 输出。

## 使用与安装

下载 [v0.3.1 预览版](https://github.com/bigccc/XiaoShuoAgent/releases/tag/v0.3.1)：[Apple Silicon DMG](https://github.com/bigccc/XiaoShuoAgent/releases/download/v0.3.1/XiaoShuoAgent-0.3.1-arm64.dmg) · [Intel DMG](https://github.com/bigccc/XiaoShuoAgent/releases/download/v0.3.1/XiaoShuoAgent-0.3.1-x64.dmg)。发布页另有 ZIP 与 SHA-256 校验文件，详见[首次安装指南](docs/installation.md)。

要求 macOS 13.0 或更新版本（依据 Electron 44.5.1 的应用 Info.plist）。Apple Silicon 使用 arm64 包，Intel 使用 x64 包。将 DMG 中的 `XiaoShuoAgent.app` 拖到 Applications，或解压 ZIP 后复制应用。使用者无需安装 Node、Python或数据库。

当前预览版没有 Developer ID 签名或 Apple 公证，首次打开可能需要在系统设置中确认。Intel 包在 Apple Silicon 的 Rosetta 环境验证，原生 Intel 设备尚未验收；详见 [验证记录](docs/verification.md)。

1. 在书架新建作品，书名可留空。作品内只显示「创作、看稿、故事资料」三项主菜单，设置位于底部，导出和待处理位于作品顶部。
2. 在「设置 → AI 连接」选择服务商、粘贴密钥。DeepSeek 预设自动填写地址与创作模型；预设依据 [官方首次调用文档](https://api-docs.deepseek.com/zh-cn/)（2026-10-13 核对）。其他服务在高级设置中填写。原有连接继续保留，密钥留空保留已有保护；保存不调用模型，测试连接会产生少量实际用量。
3. 新书可选「我有一个想法」或「帮我找个灵感」。作者看到「定故事 → 做准备 → 开始写」三步。确认故事方向后，助手集中准备必要设定与大纲，作者查看后整体确认；仍可随时「先写一段看看」。空白、待同步或失效的成果不会自动确认。底层四份阶段成果及历史仍可在「查看具体成果」中单独编辑。
4. 创作页宽屏为聊天与当前成果，最小窗口切换「聊天／稿件」。写作阶段可设置一次几章、每章大约多少字，再开始连续写作；默认认真定稿，也可选择“快速试写”先保存一章未检查草稿，编辑后继续认真定稿。也可直接说「写完前五章」或「接着写五章」。新稿逐章保存、检查并有限修订；正文、设定与阶段成果自动保存并保留历史。
5. 看稿包含阅读、结构导航、正文与版本、检查问题、待审稿与记录；故事资料包含作品信息、人物与世界、状态与伏笔、文风与声音、故事规划、素材库。已有正文的多章改稿先生成待审稿，比较差异后按章或整批采纳。作者手改或参考来源变化仍会阻止旧回复覆盖最新稿件。
6. 顶部「待处理」包含连续写作、改稿与旧任务记录。所有 AI 操作直接执行，不再要求费用确认或追加金额、累计 Token 预算。模型价格为可选统计信息，缺少价格仍可调用，费用显示未知。保留用量、费用估算、手动暂停/取消和单次输出上限；旧预算暂停任务可以直接继续。
7. 专业参数与用量收进高级设置／技术详情，阅读范围、原文证据和未完成状态仍直接可见。相关页面的「更多创作操作」保留旧规划、生成、素材提取、来源复核与候选审阅流程。素材和连接表单离开时仍保护未保存修改。
8. 对话与共识重启后保留。空响应自动重取一次，格式错误自动整理一次；恢复共用最多3次请求、4分钟时限。错误、截断和取消不把半份回复写成正文。原始回复与恢复记录按需查看，详见[恢复机制与验证](docs/conversation-recovery.md)。

对话会使用当前草稿作为上下文，默认总资料窗口为 48,000 字符，另纳入最多 12 轮、18,000 字符的近期对话及已保存共识。超限会显示阅读范围提醒，未完整纳入的旧章节、设定或阶段成果不能被模型整体覆盖。单份阶段成果最多 30,000 字符；过长的旧设定以明确标注的索引接续，原资料全文不裁剪。阶段状态作为作品可选字段随当前 SQLite 数据和作品包保存，旧作品无需额外迁移。每轮单次输出上限为 16,000 Token，多章范围为 32,000 Token，仍受模型自身限制；不会无限自动续写。对话中的情节判断由当前模型完成，独立、带原文证据的一致性检查在「看稿 → 检查问题」中。

对话与连续写作可按作者消息、当前正文和任务计划中的关键词，召回同作品当前故事位置之前的已确认旧章原文；需要复核的旧章不纳入。支持有效人物/地点名称与明确的别名行，最多6处、每处480字符，在原上下文上限内加入，不增加模型调用。聊天可展开「本次参考的远章原文」，连续任务显示最近一次逐章参考；源修改后会提示旧版本，下一次调用从当前正文重新召回。片段不能获得覆盖整章的权限，检索命中不等于检查全书。[优化路线图](docs/optimization-roadmap.md)六阶段的开发实现已交付，第一阶段采用本地关键词召回，语义检索仍为后续探索；验证见[远章召回记录](docs/context-recall-verification.md)。

在「故事资料 → 状态与伏笔」记录事件、位置、伤势、物品持有人、角色知情与关系。AI提取和连续写作附带的状态先保存为候选，作者核对原文、确认来源正文后再采纳；计划、猜测、谎言与回忆不作为当前事实。已采纳状态保留独立快照，待审编辑不覆盖它；最新来源改变时提示复核，暂不注入旧结论。原文、历史版本和归档记录可查看与恢复。

伏笔区分计划、埋设、推进、回收和放弃；回收必须绑定埋设及回收两处原文。同一人物可关联多条不同线索。单段AI提取将回收事件先保存为事件候选，由作者补齐两边依据后确认伏笔回收。一次提取最多20章，长章分段，不设累计调用预算；暂停、失败和重启保留候选及进度，手动继续才发请求。导入的提取任务继续时绑定本机可用连接。创作最多参考20条已采纳状态的原文证据；同批临时状态只用于该连续写作任务。详见[故事状态验证](docs/story-state-verification.md)。这些新增能力已包含在v0.2.0预览安装包中，文学质量仍需作者实际评估。

可在创作稿件或「看稿 → 正文与版本」展开「本章场景」，编辑2—4张场景卡的视角、目标、阻力、转折、信息揭示、预计篇幅和钩子，保存及恢复历史。卡片是写作计划，保存不会改正文或事实账本。本章计划字数优先于作品默认，每卡篇幅合计须一致。连续写作可在同一次生成响应中准备卡片，作者已有的计划保留；模型缺少可选卡片仍兼容，不增加默认请求或逐卡强制确认。主动点击「规划本章场景」会发起独立AI请求，取消、重启与导入后需手动继续。

给卡片绑定本章原文后，可按目标/阻力、转折、视角、删冗余或补冲突生成场景待审稿。只替换绑定片段，标题和段外逐字保留，作者在「待审稿与记录」比较后采纳。原文、卡片或相关状态改变会阻止旧回复和旧候选写入。未保存卡片保护导航，未发送的修改要求关闭重开后保留。详见[场景写作验证](docs/scene-writing-verification.md)；固定200、2500和3000字fixture对照验证协议、篇幅和调用行为，真实文学质量、作者采纳率及账单改善尚未评测。

在「故事资料 → 文风与声音」选择1—6处逐字原文样本，明确认可后手工填写或提取叙述文风／角色语言卡。来源正文确认后才能提取或确认档案；AI规则先保存为候选，作者核对后启用。字段待审编辑保留原采纳规则，撤销认可、关闭、归档或来源改变均停止当前参考；不会自动回退另一份旧档案，仍有效的旧版可明确重新选择。历史恢复成关闭且未认可的候选，再复核和确认。

创作每次最多参考1份叙述文风与4份匹配角色，仅发送表达规则，不把样本文字变成剧情事实或正文覆盖权限。规则占用原上下文窗口，最多8000字符且不超过窗口四分之一；多章改稿按实际当前章匹配。生成不自动学习文风，显式提取最多一次请求，失败及重启保留档案，手动继续才调用。详见[文风验证](docs/voice-verification.md)；已包含在v0.2.0预览包中，真实盲评仍待完成。

在「看稿 → 结构导航」按场景、主支线、人物、视角与伏笔定位，每页最多40条，可按章序或文字筛选并打开原文。主支线是作者手工维护的场景计划关联，最多50条、总计1000个关联，支持跨页选择、失效关联移除、归档与10版历史。人物按姓名及最多11个明确别名作正文提及定位；候选、计划与采纳状态明确区分，不能把提及当实际在场。

来源改变、缺少视角和预期伏笔回收有依据提示，可忽略及恢复；依据再次改变会重新出现，未采纳回收候选不会隐藏原采纳埋设。选择视角、主支线衔接、人物表达、伏笔回收、删冗余或补阻力后，明确生成绑定选段或当前章的待审稿，比较后才采纳。导航不调用模型，生成待审稿会调用且受任务互斥保护。详见[结构导航验证](docs/structure-verification.md)；5000章基准验证分页与范围，不代表文学质量。当前优化已包含在v0.2.0预览安装包中。

Token 用量标明服务商报告或估算。费用按配置单价估算，Token 用量留在技术详情。模型未配置时本机编辑、版本、导出和备份仍可用。素材与模型表单采用明确保存，离开有未保存修改时会提示保存、返回或放弃。任务审阅里的规划和每份提取素材同样保护修改，切换任务、导航或关闭都会先询问；规划必须明确选择采纳，素材的审核状态按作者勾选保留。

DeepSeek 配置示例：API 地址 `https://api.deepseek.com`；当前规划／正文使用 `deepseek-flash`，检查使用 `deepseek-v4-pro` 思考模式，模型表单留空密钥可保留已有保护。当前适配器不使用 `/anthropic` 地址。写稿与规划保持非思考；官方Pro检查采用有单次输出上限的思考、JSON输出和独立复核，消耗更多Token。更多创作操作中的“本次章节字数”控制目标，偏离±20%最多修订两次，原候选保留，仍不达标则请作者处理。旧记录保留兼容。2026-10-07 已完成真实复验与修稿闭环；复杂原文仍需作者判断，详见 [质量问题修复与复验](docs/deepseek-quality-fixes.md)，[首轮历史验收](docs/deepseek-live-acceptance.md)保留原始失败证据。

### 规划长度与单次输出上限

一致性检查的新任务保留所选来源全文快照，按不超过 24,000 字符的重叠分段逐段初检和复核，任务页显示“检查覆盖：已完成 / 总段数”。取消或重启后从未完成段继续，保留进度和已发现的疑点；未完成检查不能当作全文通过。跨段较远的两处事实未必同窗出现，逐段读完不代表保证检出所有跨章矛盾。历史任务若在创建时已截断，只能检查已有快照，需新建任务才能读取完整当前来源。

来源窗口、版本、规则、模型配置及作者要求相同的有效检查结果可本地复用，命中仍核验逐字依据；改变来源后只重查依赖窗口，并显示本次复用与新检查段数。逐章检查与跨章独立复核各自保留用途，不能互相代替。失败、中断或陈旧结果不能复用成通过；相同证据的疑点不重复建档，作者已处理状态保留。缓存不随作品包导出，导入副本重新检查；历史用量不会清零，未知用量保留完整调用预留。详见[检查与成本验证](docs/check-cost-verification.md)；确定性对照验证调用行为，真实漏检/误报及账单未评测。

规划与写作的单次参考上下文仍有上限；短设定未用完的额度会分配给长内容，超限在任务记录中披露。允许生成 30 万字规划，不代表后续一次模型请求能完整读取 30 万字。字数修订与首次生成一样纳入已生成的同批前章候选。

规划界面使用“规划建议字数上限”（默认 10,000，最多 300,000 字，含标点、不含空白），表示整份建议含续写的累计上限，不要求模型写满，也不修改作品的目标总字数或每章字数。“本次章节字数”只在正文界面显示。

Token 用量与费用估算可在任务详情查看，不限制累计消耗。“规划单次输出上限（Token）”默认 8,000，最多 32,000，仍受模型自身能力限制。达到单次输出上限时保留片段，可手动继续；达到规划字数上限则停止并提示结果可能不完整。技术重试仍有上限。旧规划任务未保存单独字数限制时使用 300,000 字兼容上限。

## 连续写作 Agent

在创作对话中说「帮我把前五章都写完」，助手会补齐到第5章；已有前两章时只新写第3—5章。「接着写五章」则从现有最后一章之后新增五章。一次目标最多100章，无法明确识别的多章执行请求会提示说明范围，不静默退成单章。普通讨论、试写与明确改稿沿用原有流程。

主进程使用 LangGraph JS 安排必要规划、逐章生成和一次逐窗检查；有证据的事实冲突最多局部修正一次并验证，默认不再进行整批跨章复核。现有模型接口和本机 SQLite 继续使用，不需要 Python 或额外数据库服务。任务计划保存在任务中，遵循当前正文与已确认的阶段资料。补齐及续写跳过已有非空正文；作者主动修改旧章仍先生成待审稿，手改后的正文受到保护。需要改变已确认人设、主线或结局时暂停询问。

写前在本地整理有来源的参考摘要及人物状态、承接提醒，生成与检查使用同一套约束，不增加模型请求。新稿问题合并局部修正，随后验证改动片段及关联依据；未解决问题集中呈现处理方向。点击“按推荐处理并继续”执行一次实际修正，普通续跑不重新授权改稿。证据不足的疑点直接保留为未证实提示，不追加整理请求。详见[本版设计](docs/simpler-authoring-design.md)。

任务卡分开显示已保存章数与已检查章数，并提供暂停、继续和取消。一次局部修正后仍影响后文的事实冲突会暂停；字数、文风和节奏只提示，不自动整章重写或阻塞后续章节。检查要求原文证据，不保证检出所有跨章矛盾。源版本变化时重新检查失效部分，不用旧候选覆盖新稿。

规划、生成、检查、修订和重试按每次请求当时的模型价格及实际用量记账，不再拦截金额或累计 Token 消耗。金额使用整数微元保存；缺价格或用量明确标记未知，不冒充免费或完整账单。首次建立账本前自动备份数据库。每个检查窗保存进度；重启后手动继续，从已保存阶段恢复。LangGraph负责路由，持久恢复由应用任务记录提供。

任务随v9数据库、作品包和自动恢复备份保存；对应迁移前创建一致备份（v8→v9为before-v9），仍可导入v1–v8作品。导入副本重新映射记录，不携带模型密钥或自动续跑。详见[设计](docs/continuous-writing-design.md)及[验证记录](docs/continuous-writing-verification.md)。

## 长篇阅读与改稿

打开作品后，左侧「看稿」进入连续阅读。目录只渲染可见部分，正文按邻章读取；可按章号／标题定位、搜索正文原文、筛选未审和待处理章节。字号、行距和阅读宽度可调整；切换模式和重启恢复到原段落。按章节范围建立分卷，Agent 可先提出分卷建议，再手动采用。

在阅读或审阅中选中文字，可交给 Agent；审阅模式还可记批注、选一条或多条批注改稿，再由作者复核关闭。审阅状态独立于草稿／已确认：已审正文修改后自动显示待复核，可查看上次已审稿与当前正文的段落差异。原文已变且引文无法唯一定位时，保留批注并提示重新定位，不跳到重复引文的错误位置。

对话输入区可选择当前章、章节范围或全书改稿；直接生成待审稿。全书任务按章读取完整正文，最多纳入有界邻章参考与资料，显示实际已检查范围与未纳入资料。多章待审稿按页查看，可按章或批次采纳；关联资料须与所有相关候选一致后集中采纳。关键剧情歧义可回复澄清后继续。暂停、取消或退出均保留已有候选，重启不会自动产生模型调用。单章完整来源超过上下文限制时会暂停，不截断覆盖正文。覆盖完所有章也不等于保证发现一切跨章矛盾。

规模与真实模型验证见 [长篇阅读验证](docs/long-form-verification.md)。

## 备份与数据

正常应用使用 Electron 的 `userData`，macOS 一般位于 `~/Library/Application Support/小说工坊`（已用未覆写的最终 arm64 应用实际确认）；数据库为 `works.sqlite`。**不要直接复制运行中的数据库主文件作为备份。** 在“导出与备份”选择完整作品包 `.novel`，再在另一台 Mac 导入为独立副本。模型配置表与明文／密文密钥不进入作品包；任务历史仍保留模型名称、接口地址等非密钥参数以便追溯，导入不会自动创建可用的模型配置，换机后需重新配置模型。

每 15 分钟内容变化时产生一致的自动恢复文件，`userData/recovery` 保留最近 20 份，关闭时也尝试保存恢复快照。恢复文件可以通过“导入作品／恢复备份”选择。自动恢复错误会显示在界面；重要迁移前请另存手动作品包。TXT 为 UTF-8，Word 导出为真正的 DOCX。使用过创作对话的作品默认包含当前草稿；其他作品沿用仅已确认章节的默认值，导出前可切换。数据库会在对应迁移前自动创建一致的 SQLite 备份，v8→v9 的备份标记为 before-v9；作品包与恢复包为 v9，携带关联、同步历史、分卷、批注、阅读位置、审阅基准、改稿及连续写作任务、状态记录与提取进度、场景卡历史及规划/定向任务、文风样本/采纳/历史与提取任务，以及结构主支线、关联和提醒选择/历史，继续接受 v1／v2／v3／v4／v5／v6／v7／v8。导入副本重映射关联 ID；待审稿与暂停任务可在副本中处理。单个导入作品包上限 512 MB。

概要对应书名、题材、简介与背景；设定对应人物、世界、地点、文风与节奏；大纲对应主线、全书大纲与近期章纲。全文编辑先保存本机草稿；后台整理在停止编辑五秒后自动进行并记录用量，故事资料中的修改直接更新已关联阶段，不额外调用模型。未分类内容保留为补充说明。待同步、失败或冲突会阻止推进、正文生成及检查；可重试、取消或选择实际冲突中的版本。历史恢复同时恢复关联资料，涉及后续独立修改时先显示差异。移除只归档该阶段管理且没有其他引用的记录，不自动删除独立手工资料。字数目标保持作者设置，前期计划不会写成已发生的时间线或角色知情事实。

密钥由 Electron `safeStorage` 在主进程通过 macOS Keychain 保护，只在实际保存或使用凭据时检查和访问，不在离线启动时调用可阻塞的可用性检查；运行时不可用时拒绝保存非空密钥，并保留本机创作能力。不能从界面读回密钥。正式发行需要一致签名并验证升级后的钥匙串访问。

## 开发

开发要求 Node.js 22.13+，本机已验证 Node 22.22.1 / npm 10.9.4。依赖版本写死并由 `package-lock.json` 锁定，无需修改全局工具。

```sh
npm ci
npm run dev         # Electron + renderer 热更新
npm run build       # out/main、out/preload、out/renderer
npm start           # 启动构建结果
npm run typecheck
npm test            # 真实 SQLite / loopback HTTP 服务层测试
npm run e2e         # 构建并运行真实 Electron 控件工作流
npm run benchmark:scenes # 历史写作器与场景响应的固定协议对照（需完整Git历史）
npm run package     # 当前架构 .app
npm run make:arm64   # Forge .app + ZIP + DMG
npm run make:x64
```

开发主进程和界面职责分离；只经 `window.novel.invoke(command)` 与 `snapshot()` 调用受控 AppServices。主进程验证发送者主框架及 URL，禁用 Node 集成、启用隔离与沙箱；无任意路径或凭据读取接口。SQLite 使用 Electron 内置 `node:sqlite`，不需要原生数据库重建。

E2E 仅在独立临时目录运行，使用 Chromium 测试钥匙串隔离假密钥，HTTP 仅访问当前测试创建的 loopback fixture，不调用外部付费模型。测试不代表真实系统钥匙串授权或凭据保护已经验收。`NOVEL_TEST=1` 配合绝对 `NOVEL_DATA_DIR` 可显式选择测试数据目录；正常打包应用忽略该覆盖，测试不替换真实作品。测试通过主进程对原生文件选择框的边界注入所选临时文件，所有后续解析／持久化／导出仍走真实 AppServices。

`scripts/verify-*-live.ts` 为手动真实模型验收工具，会读取当前 macOS 用户已保存的模型连接，并在隔离临时目录中调用付费服务；它们不属于 `npm test` 或 `npm run e2e`。`docs/` 中的历史验收证据与截图使用测试样本，记录中的本机路径仅用于追溯。

打包结果在 `release/`；Forge 自定义 DMG maker 仅调用系统 `hdiutil`，没有额外安装工具。默认以临时签名（ad hoc）重新密封整个应用包，避免重命名 Electron 后残留无效签名；临时签名不验证开发者身份，也不等于通过 Gatekeeper。可选 `MAC_SIGN_IDENTITY` 使用 Developer ID 证书，`APPLE_NOTARIZATION_PROFILE` 选择已有 notarytool keychain profile。开发者签名／公证须由持证者配置，项目不含 Apple 或模型凭据；本次未使用这些变量。

对真实 arm64 包运行同一组验收：

```sh
NOVEL_PACKAGED_EXECUTABLE="$PWD/release/XiaoShuoAgent-darwin-arm64/XiaoShuoAgent.app/Contents/MacOS/XiaoShuoAgent" npx playwright test
```

打包、自动测试、真实 API、长篇阅读、两架构设备安装与签名公证的状态分别见 [docs/verification.md](docs/verification.md)。
